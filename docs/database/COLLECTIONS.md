# Collection Inventory

Names and purpose only — schemas are defined when each owning feature module is built, not before, per "work module by module." Check here before adding a new collection to avoid duplicating an existing one under a different name.

| Collection | Purpose | Owning module | Embed/Reference notes |
|---|---|---|---|
| `users` | Login identity: `mobile` (globally unique, indexed), `password_hash`, `role`, `is_mobile_verified` + base fields (`status` doubles as `pending_password`/`active`/`disabled`) | Auth (implemented) | No profile data (name/address/etc.) — that's future User Management/Customer/Referral Partner collections, referenced by this doc's `_id` once they exist |
| `sessions` | One row per issued refresh token: `user_id`, `token_id` (jti, unique), `refresh_token_hash`, `device`/`browser`/`operating_system`/`ip_address`, `login_at`/`logout_at`/`last_activity_at`, `status` (active/logged_out/revoked) | Auth (implemented) | References `users`; Session Management data source (no UI screen yet) |
